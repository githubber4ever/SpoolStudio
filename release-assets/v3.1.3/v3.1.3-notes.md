# Spool Studio 3.1.3

This update adds explicit tag storage selection and fixes RFID colors disappearing when Spoolman cannot be reached.

- Choose **Both (compatibility)**, **Only card_uids**, or **Only native tags** per Spoolman server. Both remains the default; existing native-only preferences are preserved.
- Reading, linking and unlinking use only the selected store(s). Single-store modes leave the other store untouched. When reading both, a native owner takes priority.
- Match the app setting to the printer's tag storage. Changing the app mode does not migrate data. The current form selection and scanned UID are cleared on a mode change or completed migration to prevent stale links being reused.
- Readable OpenSpool tag contents, including color, are displayed immediately and retained if the server lookup fails. Already decoded Bambu color and weight can also be displayed offline.
- Offline tag contents and embedded spool IDs are not treated as confirmed server assignments. A successful server lookup still takes priority. A UID-only tag cannot provide color offline.
- **Manage tag links** and **Unlink** now use clearly bordered buttons. Toolhead cards retain the compact pencil icon for assigning or clearing a spool.
- The optional filament-name action is now a bordered **Use color name: …** button and is hidden when the existing name already matches the suggestion, including differences in capitalization or surrounding spaces.

Native tags require Spoolman **0.27.0 or newer**. Firmware **2.0.0-paxx12-24** still needs `card_uids` or Both. The firmware's native storage switch and reverse migration require a build containing [PR #867](https://github.com/paxx12-snapmaker-u1/SnapmakerU1-Extended-Firmware/pull/867), merged on 2026-11-04.

Validation: 143 automated tests passed including the UI refinements; debug build succeeded and Android Lint reported 0 errors. Five live U1 checks passed with Spoolman 0.27.0: offline color, legacy-only linking/moving, both stores, separate clear/unlink behavior, and native migration/reassignment/return migration. Native tests used **2.1.0-paxx12-pr867**; initial legacy tests used **2.0.0-paxx12-24**. The subsequent UI refinement does not change these backend operations.
